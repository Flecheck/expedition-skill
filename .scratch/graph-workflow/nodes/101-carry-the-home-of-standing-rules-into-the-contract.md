# Carry the home of an effort's standing rules into the manager's contract

Type: implementation
Status: open

## Question

*Surfaced by [Rules added to one effort's map, and what makes them legitimate](93-effort-scoped-custom-rules.md)'s
worker, and pasted as it wrote it.*

> The manager's shipped contract has a `### Standing steering, and standing instructions of one effort` section that
> says a standing scope or emphasis is written into the map and that a human's standing instruction is recorded as
> theirs — but it does not say that this is where a rule of any kind lives, that the map is usually the only home a
> rule ever gets, or that only the human decides whether a rule reaches a shipped skill file. Write those in.

**Blockers, in the worker's words:** *"none."*

## Acceptance condition

*Written by node 93's worker. Pasted as it wrote it, and not the manager's.*

> `.claude/skills/expedition/SKILL.md`'s section headed `### Standing steering, and standing instructions of one
> effort` states all four of the following. The wording and the order are the writer's; each must be findable in that
> section as a statement rather than as an implication.
>
> 1. A standing rule the human gives — about what to work on, or about how work is done — is written into the
>    effort's map when they state it. That is what makes it bind on that effort, and it binds nobody until it is
>    there. This holds for rules of conduct and not only for steering about what gets worked.
> 2. The map is the ordinary home and usually the only one. On most efforts the workflow's own skill files are not
>    modified at all, so a rule the human gives lives in the map and nowhere else, and the next effort starts without
>    it.
> 3. A rule reaches a shipped skill file only where the human says so, and it does so as a node. The manager never
>    carries one into a shipped file on its own judgement, including where it judges the rule to be about the
>    workflow rather than about the effort. Where the human says nothing about a rule's scope, the rule is the
>    effort's alone.
> 4. Every worker on an effort is bound by everything in that effort's map whatever a rule's origin, so no scope
>    marking is owed for a worker's sake and the map carries no per-rule scope field.
>
> The existing paragraph beginning *"Some of what binds you on a given effort is a **standing instruction of that
> effort's human**"* is kept, its recording duty being what the four statements build on.
>
> No text is deleted from the file. Where a sentence in that section is superseded by one of the four, it is marked
> as superseded and left where it is, with the new text added around it.
>
> Nothing in the section is cited by line number; a citation to another part of the file names a heading or quotes a
> phrase. The section remains reachable and readable by its own heading, so a reader following a pointer to it reads
> that section and nothing else.
>
> No other file is changed. In particular this node does not touch `map.md`, the other seven shipped skill files, or
> `CONTEXT.md`.

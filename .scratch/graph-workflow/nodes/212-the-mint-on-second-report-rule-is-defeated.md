# The rule that mints a node on a repeated retrospective item has been defeated by its own test

Type: grilling
Status: claimed

Blocked by: none

## Question

worker, and pasted as it wrote it.*

> Flag `141.3` set its own falsifier — *"a later reader should treat a fourth unrecorded
>   repeat as evidence against it"* — and node 183 established that the item has now been reported six

>   unchecked. What replaces it? The defect is that the rule puts a judgement on the path — the manager
>   noticing a repeat — and node 183's remedy removes judgement only from the recording of numbers, not

>   preference for simple prose over machinery, and node 183 confirmed that refusal for numbers; whether
>   it survives for items is what this node asks. Options span keeping the rule with its weakness stated,
>   moving the count to the worker, making the count a derivation over the retrospective annotations, and
>   dropping the threshold in favour of something else.

Q1. What makes "the same standing item" identifiable

ASK:           Does the retrospective start *naming* the standing item it reports — the worker proposing

               context sits in the worker, not the manager.

Q2. What a crossing earns

ASK:           When an item's count crosses, does a node get minted automatically — and at what count —

               effort whose close is triggered by that frontier emptying. At three, about 14 new. At
               five, about 7. Ranking keeps the weight where you put it, on repetition, and spends it
               on ordering rather than on volume; and it is a pull from a visible list at a moment the
               manager is already choosing work, rather than a push that depends on remembering.

ALTERNATIVES:  - Automatic mint at two, made to actually work. Honest to the rule as written, and it

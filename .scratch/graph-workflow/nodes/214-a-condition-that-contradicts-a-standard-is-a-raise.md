# A condition that cannot be honoured with a standard is a raise, in both workers' contracts

Type: implementation
Status: claimed
Supersedes: 208

Blocked by: none

## Question

*Directed by the human at [node 200](200-collapse-the-rules-files-two-map-history-statements.md)'s gate, in their
own words.*

> If both the checker and implementer knew it, I would have expeted a raise at least.

**What happened, and it is the whole of the ground.** Node 200's acceptance condition demanded, in clause 3, that
the finished `map-implementation-rules.md` state which supersession route the retired text took. That file's own
admission test — a standard the work is held against — sends exactly that material to `map-history.md`. **Both
agents saw the contradiction, both recorded it, and neither raised it**, so the collision reached the human only
after the work was finished and checked, in the file itself:

- the worker, at flag `200.1`: *"Both cannot be honoured in full… Decided rather than raised: the condition is
  satisfiable either way and the cost of the wrong choice is one sentence."*
- its checker, in a question handed back alongside its `PASS`: *"complying with clause 3 puts into the working file
  a line that file's own test would send out of it… The wording is the condition's own and so was not the worker's
  to depart from, which is why this is a question and not a finding against the work."*

**Neither was wrong about its own authority**, which is what makes this a defect in the contracts rather than in
either agent. The implementer's contract has it raise when its **premise** is broken, and this worker judged its
premise intact because the clause was satisfiable; the checker's contract routes what it cannot settle into a
question that does not wait. **Nothing in either file says that a clause which cannot be honoured together with a
standard is itself a broken premise.** What this node decides is the wording that says so, in both contracts, and
what the trigger is precisely enough that it does not fire on every hard clause.

**Two things this node now has that it did not.** First, **the cost of a checker's raise is stated**: it withholds
an outcome the checker is able to give, so a rule that makes a collision raisable has to be worth losing that
outcome. Second, **the manager's gloss in that spawn was wrong** and is flagged at `200.3`: a checker's raise does
stop the check, and only a question handed back alongside an outcome does not. **Whoever writes this node's rule
should assume the manager's summary of the raise mechanics cannot be trusted and read the two contracts.**

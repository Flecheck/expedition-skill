### 1. What the direction binds, and what it does not

Their direction — *"I also would want the skill to not depend on mattpockock"* — is about the product. **The shipped
corpus already satisfies it, verified in the tree rather than taken from the record:** `grep -rn "mattpocock"
.claude/skills/expedition*/` returns nothing, and a second search for the bare names returns one line,
`expedition-checker/SKILL.md`'s *"Invoke it with the givens supplied"*, which names no skill at all. After node 133
landed, **no shipped file names any skill by any name.** That is stronger than node 113's worker could state, which
predicted this state rather than measuring it.

It does **not** bind this effort's own never-shipped material. Two grounds, and the second is the human's own word:

- **[Node 138](138-where-the-rules-a-checker-is-held-to-live.md)'s amendment reaches a *shipped file* and this is not
  one.** Ground rule 5's own text says so: *"specific to this repo, is never shipped."* Outside that exception [node
  93](93-effort-scoped-custom-rules.md)'s default holds, and the rule is the effort's alone.
- **They had already spoken on this exact line.** After the no-plugin direction arrived, they approved node 113,
  whose recommendation ends *"the skills stay named in `map.md`'s `## Notes`"* — the `Skills every session should
  consult` line. They kept it.

### 2. The half this node was told was already answered, and was not

This node was updated in place to say that half its question was settled by the human's act of barring
`mattpocock-skills:code-review`, leaving only ground rule 5. **That reading does not survive their own sentence.**
Their words are *"we shouldn't use matt pockock skills code review skill as it is **too generic**"* — the ground is
the skill's content, not its being a plugin. So barring it is evidence about that skill and not about the plugin
question, and **the whole of this node's question was open, not half of it.** The review route's disposition is
unchanged by this finding: that skill stays barred, on the ground they gave.

### 3. The repair, made on a different ground from the direction

The direction does not require it. The fragility does, and it is measured rather than feared.

**Of the 13 `mattpocock-skills` names this machine's own usage record shows the human has invoked, 7 no longer
resolve** — `grill-me`, `grill-with-docs`, `implement`, `setup-matt-pocock-skills`, `to-issues`, `to-tickets`, and
`writing-great-skills`. That last one **is the standard this effort reviewed its entire shipped corpus against at
[node 47](47-review-shipped-skills.md)**, and is in that node's title. Of the 11 names registered today, 5 appear
nowhere in the usage record. The plugin is registered `@inline` with **no path on disk**, so nothing in this
repository can pin a version or read it when it is gone.

**So the repair:** ground rule 5 names what the standard demands, held as text in this effort's own rules file, with
`mattpocock-skills:writing-for-agents` permitted as one route to the same material and the standard holding whether
or not that name resolves. The standards list a checker is handed points at that text rather than at the plugin
skill.

**It mints nothing.** The objection the surfacing worker raised against reaching ground rule 5 was that replacing
`/writing-for-agents` *"would mint a third shipped-discipline deliverable on top of node 130's."* That objection is
about **shipping** a replacement. Copying demands into `.scratch/graph-workflow/` ships nothing: that file is this
effort's working notes and is discarded when the effort ends. The count node 130, node 145 and this node share is
unchanged at two.

**It partly discharges a fog item.** `map-manager-only.md` records *"nothing watches a standard that lives outside
this repository"* as unspecified, on the strength of one instance. This node adds six more instances and removes this
effort's prose bar from the exposure — the fog item survives for anything else external, with one fewer claimant.

### 4. What this corrects in `map.md`

The no-plugin bullet asserts *"What it reaches, which is more than the contracts: the `Skills every session should
consult` line above, and **ground rule 5**"*. **The human has now said it reaches neither.** That sentence is

### 5. Where this meets nodes 145 and 130, without claiming either

[Node 145](145-whether-the-workflow-ships-its-own-reviewing-discipline.md) asks whether the workflow **ships** a

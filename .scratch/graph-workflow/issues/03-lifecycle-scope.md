# How much of the lifecycle the workflow owns

Type: grilling
Status: resolved

## Question

Does the workflow own the whole route from loose idea to finished code, sit downstream of a cleared wayfinder map, or hold implementation work only?

## Answer

**One graph, idea to perfect code.** Decision issues and implementation issues live in the same graph, and the workflow supersedes wayfinder for efforts it is run on. Fog and destination-naming carry over from wayfinder.

Reasoning: the premise is that implementing something feeds back and reshapes decisions. If the decisions were all settled in a separate, already-finished wayfinder run, no live decisions remain for implementation to reshape — the feedback loop only exists when both kinds of node share one graph.

Consequence: this workflow must absorb everything wayfinder does (destination, fog, frontier, blocking, one-ticket-per-session discipline) *and* add implementation nodes and revision. It is a superset, not a companion.
